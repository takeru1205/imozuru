# 原典をたどる

## 問いと地図

[map-format.md](map-format.md) の形で問いと「要る主張」を作る。既定は3〜6個。少なくとも1つに依頼の具体的な条件を含め、半分以上は効果・限界・不足など本文を読まなければ答えられない問いにする。知見が集まる場も調べる。コツや定番のやり方を探す場合は、その元になった原典・研究の有無を含める。

既存調査なら map.md と log.md の未達・次の手がかりから再開する。問いが変われば主張も更新し、理由をログに残す。

## 探索

入口では、同じ問いを異なる2つの探し方で探す（英語と日本語、用語検索と総説・教科書など）。用語と出典 URL、人と代表作、知見が集まる場、定番資料の題名・著者・年・公開 URL を地図にまとめる。所属・数字・公開状況は本文で確認するまで「未確認」。

分野に応じて論文・個人の実践記録・動画・公式資料を選ぶ。場は固定のサイト一覧から選ばず、実際に知見が集まる場所を調べる。用語が分からなければ入門資料や総説の引用を入口にする。見つからない種類があれば言語・用語・情報源を変える。

各探索の結果を「見つけた／探したが無い／探していない」に分け、次の手がかりを残す。複数の仮説があるときは別々に探して比較する。

探索は自分で順に実行できる。サブエージェントが利用可能かつ許可され、独立した探索に有益な場合だけ同時2本まで使ってよい。モデルを固定しない。委譲する場合は問い・探し方・既知の一覧を渡し、検索と読み取りだけを頼む。保存と地図への統合は自分で行う。起動・完了・中止を log.md に記録し、比較する探索が完了してから終了を判断する。

## 原文までたどる

手がかりから、繰り返し引用される資料・総説・本人の記録を選び、次の動きでたどる。全部を毎回行う必要はない。

| 動き | 論文 | 個人の発信 |
|---|---|---|
| 後ろへ | 参考文献、`chain.py refs` | 記事中のリンク・参考にした人 |
| 前へ | 被引用、`chain.py cites` | 紹介・引用している記事 |
| 著者で追う | 他の論文、`chain.py author` | 過去記事・チャンネル |
| 場・近傍を見る | 学会・雑誌・同じ号 | タグ・フォーラム・関連記事 |
| 言葉で引き直す | 地図に増えた専門語 | 俗称・略語も含める |

`fetch.py` の `OK` の資料だけを原文の表に登録し、必要な箇所を読んで主張にファイル・行番号・短い引用を付ける。`FAIL` は URL と理由をログに記録する。取得できない定番は著者・研究室・大学リポジトリ等の公開版を探す。道具の使い方と制限は [tools.md](tools.md)。

## どこで止めるか

入口の地図づくりを0周目とする。その後、原文を取得して引用・リンク・著者のいずれかを少なくとも1回たどるまでが1周。入口だけで充足したように見えても、通常は1周を完了してから終了を判断する。ユーザーの時間・回数制限やアクセス不能は優先する。

次のいずれかに達したら探索を終え、理由を log.md に記録する。

- **充足**: 全主張に、本文で確認した原文の場所と短い引用が付いた。
- **飽和**: 同じ問いを異なる2つの探し方で調べ、この周で挙がった人・資料の7割以上が周の開始前から地図にあり、新しい用語もほぼ出ない。重複を除いた分母・分子を記録する。自分が拾った既知資料も含める。異なる仮説同士の結果や、取得した当たりがゼロの空振りでは飽和を判定しない。7割は経験的な目安であり、網羅性の証明ではない。
- **周回上限**: 既定の4周に達した。ユーザーが上限を指定したらそれを使う。
- **アクセスの壁**: 未達部分が有料・ログイン・取得制限の先にしかなく、他の公開先も見つからない。
- **依頼の上限**: 時間・回数などの指定に達した。充足や飽和を装わない。

続ける場合は次の手がかりをログに残して進む。終了時には未達・部分的な主張とその理由も残す。ブラウザで読める公開資料は、利用可能で許可されたブラウザで確認できる。既存の許可を再度求めず、新たな権限が必要なら対象を示す。取得制限を回避する細工はしない。

## 仕上げ

[report.md](report.md) に従い抜き書きを照合して report.html を作る。自分が起動した未完了の処理・検索役は回収または停止してログに記録する。

最初に report.html のパスを示し、終了理由、主張ごとの原文の場所、未達と重要な未取得 URL を伝える。特に読む価値がある原文を2〜4本、読む箇所とともに案内してよい。要約・解説は依頼がある場合に添え、抜き書きとは区別する。ユーザーから探索への感想が届いたら、log.md にそのまま記録する。
