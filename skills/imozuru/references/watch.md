# 新着を確認する

`$imozuru watch <話題>` や「この分野の新着を見て」で使う。新着確認だけなら深掘り・抜き書きレポートは不要。

## 見張る先

既存の map.md と watch.tsv を確認する。地図がなければ、確認できた公式ブログ・公開フィードなどで最小の地図（問い・場・人）を作る。場所の見当がつかない場合だけ [research.md](research.md) の入口探索を使う。

`python3 "<skill_dir>/scripts/watch.py" add "<topic_dir>" "<url>"` で登録する。RSS の有無は推測せず add の結果で確かめる。Qiita・Zenn・note・Reddit・YouTube のチャンネル・RSS/Atom のあるブログ・arXiv の検索フィードに対応する。X・pixiv のように対応フィードのない場所は監視できない旨を伝える。

既存の登録一覧は `python3 "<skill_dir>/scripts/watch.py" list "<topic_dir>"` で確認できる。

## 取得と引き渡し

```sh
python3 "<skill_dir>/scripts/watch.py" check "<topic_dir>"
```

初回は直近14日。`--days N` で期間を変える。既に見たものも含め期間を広げて出し直すときは `--fresh` を付ける（初回の期間外も既読として記録されるため）。結果は `watch/<日付-時刻>.md` に残る。新着なしの場所も期間に関係なく最新1件が出る。

一覧ファイルへのリンクと、題名・日付・場所・フィード原文の冒頭1行を示す。要約や点数は既定では付けない。件数が多ければ依頼に沿って絞り、絞ったことと全件ファイルの場所を明示する。取得失敗と新着ゼロを区別し、新着なしの場所の最新1件も短く添える。

原文の取得はユーザーが選んだもの、または既存の要る主張に関わるものに絞る。新しい人・場・用語が繰り返し出たら、地図の次の手がかりに記録する。監視範囲の拡張が依頼の範囲外なら提案にとどめる。単発の新着確認を定期実行に変えない。
