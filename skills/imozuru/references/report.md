# 抜き書きのページ


原文を何十本も落としただけでは読まれない（英語の PDF や1時間の字幕のまま）。かといって要約すると早すぎる閉じに戻る。だから止めたら、**抜き書き**（Ellis の extracting）でページを作り、それを最初に渡す。

1. `<topic_dir>/extracts.json` を書く。要る主張ごとに節を立て、原文から**そのまま切り出した文**を並べる（ファイル・行・必要なら `end`）。英語には `ja` に訳を添える（訳だと分かる印がページに付く）。印（〔本人〕自動字幕 など）は `mark` に。2段組の PDF のように左右の段が1行に混ざる所は、抜き書きを「…」で区切ると区切りごとに順に照合される（省いたことはページにも「…」で見える）。食い違いは `disagreements` に並べるだけで、どれが正しいかは書かない。届かなかったものは `unreached` に。以下の形を使う（インストール済みスキル単体で作成できる）
   形（report.py の冒頭と同じ。`?` は省いてよい）:
   ```
   {"title", "question", "stopped",
    "claims": [{"claim", "status": "付いた|一部だけ|付かなかった", "note"?,
                "quotes": [{"file", "line", "end"?, "text", "ja"?, "mark"?}]}],
    "disagreements"?: [{"topic", "quotes": [{"file", "line", "text", "who", ...}]}],
    "unreached"?: ["..."]}
   ```
2. `python3 "<skill_dir>/scripts/report.py" "<topic_dir>"` を回す。**抜き書きが原文の指定の行にそのまま在るかを機械で照合し**、1つでも合わなければ HTML を作らずに止まる（言い換えが紛れ込むのを防ぐ）。合えば `report.html` ができる。各抜き書きは「前後を読む」で原文の前後を開ける
3. 抜き書きページでエージェントが書くのは、見出し・状態（付いた／一部だけ／付かなかった）・1行の注記・訳。注記にも結論や評価は書かない（「順番は記事ごとに違う」はよい、「この順が正しい」は書かない）。注記は、誰が何をどうしたかが分かる平らな文で書く。依頼された要約・解説は抜き書きと区別して添える
4. 自動字幕の誤変換は直さずにそのまま切り出す（直すと言い換えになる）。印に「自動字幕」と書けば、読む人が動画で確かめられる

`file` は `sources/` からの相対パス（例 `sample-paper.txt`）。`line` と `end` は1始まりの行番号。字幕も照合には行番号を使い、時刻は `mark` などに添える。`text` は空にしない。

照合失敗では指摘された原文・行・引用を確認して修正し、再実行する。照合を通すために原文を書き換えない。修正不能なら未達として扱い、既存の report.html を今回成功した成果物として渡さない。
